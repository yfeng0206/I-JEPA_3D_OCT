fix(monitor): derive ETA from the iteration log, not a hardcoded constant

The monitor previously parsed epoch durations from a stdout file and fell back
to SEC_PER_EPOCH when that file was absent. For the anatomy run no stdout log
existed in the run directory, so every ETA it produced came from a stale
constant -- which is how it reported 160 h for a run whose own CSV showed
1.33 h/epoch. Run paths, start epoch and total are now environment-overridable
and the pace is computed from the timing columns the trainer writes every
iteration, with the source named in the output so a fallback is never mistaken
for a measurement.

Retargeted at the new run (anatomy_v2_ep25).
