feat(monitor): report val loss against the baseline runs each check

Validation always uses the plain 42-cell rectangle collator regardless of
training mode, which is precisely what makes val loss comparable ACROSS runs
(and, for the same reason, not comparable against train loss within a
curriculum run). The monitor now prints our per-epoch train/val beside the
envelope run's at the same epoch, plus the published oracle and random
checkpoints from the docs where epochs align.

Oracle and random kept no per-epoch logs, only plots, so their reference
points are the tabulated values in docs/experiments/pretraining/.

Context this makes visible, from the previous anatomy attempt:
  ep28  envelope 0.1215/0.1191   anatomy 0.0638/0.1288
  ep31  envelope 0.1160/0.1248   anatomy 0.0564/0.1647
Anatomy trains to a much lower train loss on its own easier 16-cell target
and scores worse on the rectangle validation task -- while nonetheless
beating envelope on downstream AUC at ep30 (0.8582 vs 0.8528). Consistent
with the repo's standing position that loss is not the quality signal.

monitor_run.py is not imported by the training process, so editing it while
the run is live is safe.
