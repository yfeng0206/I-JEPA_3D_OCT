## 16. METHOD AND LIMITATIONS

**Method.** [MEASURED] `git ls-files` enumerated 853 tracked paths. Every tracked
text file under 3 MB was read into memory and cross-referenced: for each tracked
script, the audit searched every other tracked text file for the script's
basename and for Python import forms of its module name. For each tracked
`results/`, `docs/`, `plots/`, `logs/` and `configs/` path, the audit searched for
the path and directory prefix. SHA-256 was computed over all 853 files to find
byte-identical duplicates. The build dependency set was derived by reading
`autopilot/refresh_all.py` and each script it invokes, then following imports and
the JSON filenames each script opens, rather than by inferring from filenames.

**Limitations.**

1. A script invoked only from an interactive shell, from a notebook, or from a
   `D:\jepa_phase0` wrapper would appear unreferenced here. The bucket C
   classification is therefore a strong prior, not proof. This is why section 14
   proposes archiving rather than deleting the 103 scripts.
2. Content stored under `D:\jepa_phase0\` was not inspected, per the constraint.
   Several bucket E items could be resolved by checking whether a matching run
   directory exists there.
3. The audit ran while a GPU training job was active and while the autopilot was
   writing. [MEASURED] `git status` changed between the first and last inspection:
   `autopilot/RESOURCE_MONITOR.csv`, `check_manuscript.py`, `p8_make_assets.py`,
   `paper/genai4health2026/auto/*` and `main_submission.pdf` were modified, and
   `autopilot/reports/P17_blind_review.md` was staged, during the audit window.
   Counts are as of the `git ls-files` snapshot taken at the start.
4. Two untracked files exist and were not classified:
   `scripts/probe_hf_checkpoints.py` and `scripts/score_head_on_cache.py`.
   [INFERRED] From checkpoint 099 and 100 titles they belong to the recent
   head-recovery work; decide whether to commit them before merging.
