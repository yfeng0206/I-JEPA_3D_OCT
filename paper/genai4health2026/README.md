# GenAI4Health 2026 paper package

Working directory for the NeurIPS 2026 GenAI4Health workshop submission
(Research Paper track, double-blind, 9 pages excluding references and appendix).

For what is measured, what is a placeholder, and which artifact produced each
number, read `HANDOFF.md` at the repository root first. It is generated from the
verified probe inventory, so it cannot drift from what the paper claims.

## Central claim

Guided masking helps, but anatomical precision does not. Aiming predictor targets
at retinal tissue beats unguided masking, while policies that trace the segmented
retina more faithfully are indistinguishable from it. The strongest arm
(`centroid`) uses no segmentation model at all -- it locates a band by a
per-column intensity-weighted row centroid.

Two results are reported as negative or withdrawn rather than buried:

* The `cover` arm carries an implementation defect. Predictor targets are
  truncated after placement, so its delivered masks hide less anatomy than the
  `envelope` arm rather than more. Its decline is reported; the over-coverage
  interpretation is withdrawn. See `autopilot/COVER_AUDIT.md`.
* The anatomy arms and the rectangle arms are collated differently
  (`pred_target_k`), which weakens "everything else held fixed" for that one
  cross-family contrast. Disclosed in the paper.

## Files

| path | role |
|---|---|
| `main_submission.tex` | the submission. This is the file to compile. |
| `auto/` | fully generated macros, tables and figures. Never edit by hand. |
| `figures/` | static figures, NOT regenerated by the pipeline. |
| `neurips_2026.sty` | official style file. |
| `references.bib` | bibliography. |
| `SOURCES.md` | generated provenance for every quoted quantity. |

Every number in the manuscript resolves through a macro in
`auto/auto_numbers.tex`, which is regenerated from saved per-case predictions.
No number is typed into the prose, so prose, tables and figures cannot disagree.

## Build

Overleaf: upload this directory as a project and set **`main_submission.tex`**
as the main document.

Locally, this project builds with Tectonic (self-contained; neither `latexmk`
nor `pdflatex` is installed on the development machine):

```powershell
& "D:\jepa_phase0\tools\tectonic\tectonic.exe" -X compile main_submission.tex --keep-intermediates
```

The `Fontconfig error: Cannot load default config file` message is benign.

## Regenerate everything

Do not compile by hand if you have changed or added a result. From the
repository root:

```powershell
D:\jepa_phase0\.venv\Scripts\python.exe autopilot\refresh_all.py
```

That rebuilds macros, tables, figures, the PDF, and the validated Overleaf ZIP,
and it publishes the compiled PDF back into this directory so the two cannot
drift.

Three gates run as part of the build and fail it on error:

* `autopilot/check_manuscript.py` -- undefined or duplicate macros, dangling
  references, banned phrases, stale probe counts, and raw arm keys leaking into
  a generated table instead of resolving through `\ArmBest`.
* `autopilot/p15_verify_numbers.py` -- every `AUC<Arm>Ep<N>` macro must carry the
  value measured for the arm its own name declares. No cross-arm attribution.
* `autopilot/p13_build_zip.py` -- six checks: compiles standalone, main content
  within 9 pages, no undefined references, anonymous, no unresolved
  placeholders, all graphics present.

## Adding a result

Drop the probe output in the run directory following the existing naming
convention, then run `refresh_all.py`. The inventory discovers it, macros that it
satisfies stop rendering as red placeholders, and the tables and text update
themselves. No LaTeX edit is needed.

## Anonymity

`\author{}` is empty and the ZIP validator scans the compiled PDF for
identifying terms and fails the build if any appear. Note that the wider
repository is NOT anonymous: commit authorship and some paths identify the
authors, so the repository must not be linked from the submission.
