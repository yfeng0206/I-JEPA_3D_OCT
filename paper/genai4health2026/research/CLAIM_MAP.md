# Claim map

`research/claim_evidence.csv` maps every substantive *claim* in
`main_submission.tex` to the artifact that supports it. It is a repository
artifact, not manuscript text: it costs no pages, is not `\input` anywhere, and
cannot break the build.

## Why this exists alongside the number machinery

The number-side provenance is already strong and stays exactly as it is:

- every printed value is a macro in `auto/auto_numbers.tex`, generated by
  `autopilot/p8_make_assets.py` from stored artifacts;
- `research/numbers_master.csv` and `results/downstream/ARTIFACT_MAP.json`
  record where those values come from;
- a build gate resolves each AUC macro's arm and epoch from the macro name and
  fails if the value does not match that arm's stored probe, so reporting one
  arm's number under another arm's name is a build error.

None of that catches a **claim** that outruns a **correct** number. The failures
this paper actually had were all of that kind:

- "every disease stage improves with intervals excluding zero" - true
  unadjusted, false once the ten-contrast family was adjusted;
- "we cannot speak to intersectional groups" - stated three times while the
  race-by-sex analysis sat on disk;
- a race trend described as passing correction at `q = 0.0668`, above the stated
  `0.05` threshold;
- a title asserting a comparison the body called "not identified by this
  design";
- a contribution bullet claiming as a contribution what the ethics appendix
  calls a caution.

Each was found late and by a different route. This map is the standing check
that would have surfaced them earlier.

## Columns

| column | meaning |
|---|---|
| `claim_id` | stable identifier. Prefix marks where the claim sits: `T` title, `A` abstract, `I` introduction and contributions, `S` experimental setup, `R` results, `L` discussion and limitations, `C` conclusion, `P` appendix claims the body relies on, `F` figure and table captions. |
| `section` | human-readable location. Deliberately **not** a line number: two other agents edit `main_submission.tex` concurrently and line numbers rot within minutes. |
| `claim_text` | the claim, paraphrased closely enough to find by search. Macro-expanded values are written out so the row is readable without compiling. |
| `claim_type` | `MEASURED`, `DERIVED`, `SCOPED`, `INTERPRETIVE`, `LIMITATION`. |
| `evidence_path` | the artifact. Repo-relative with forward slashes, or absolute when it lives outside the repository (`D:\jepa_phase0\...`). |
| `evidence_locator` | the macro name, JSON key path, table label, CSV column or script output line that carries the value. |
| `status` | `SUPPORTED`, `SCOPED-OK`, `PENDING`, `UNSUPPORTED`. |
| `note` | what a reviewer should know, and for anything not `SUPPORTED`, what would close it. |

### `claim_type`

- **MEASURED** - a quantity read directly from a stored artifact.
- **DERIVED** - arithmetic, a ranking or a comparison on top of measured values
  (a difference of two AUCs, a ratio, a max-min gap).
- **SCOPED** - a statement about what the design does or does not cover.
- **INTERPRETIVE** - a reading of the evidence rather than the evidence itself
  ("this design does not identify H3").
- **LIMITATION** - an admission of something absent, unrun or unrecoverable.

### `status`

- **SUPPORTED** - the artifact says what the claim says, at the claim's own
  scope. No action.
- **SCOPED-OK** - true only within a stated scope, and that scope is correctly
  stated. These are **not** defects. Two canonical examples: the label-efficiency
  reproduction bound is `0.0009` over four arms and `0.0003` over two, and both
  are correct because they are different quantities; the race analyses run on
  `19` probes and `23` probes respectively, and both counts are right because a
  per-group race summary exists for only 19 of the 23 encoder-epoch units. A
  `SCOPED-OK` row with a note is a row where the scope is load-bearing and must
  not be dropped in a later edit.
- **PENDING** - the claim could not be traced to an artifact from this checkout.
  The note says exactly what would close it. This is not an accusation that the
  claim is wrong.
- **UNSUPPORTED** - the artifact does not say what the claim says, as the claim
  is currently worded. Always accompanied by a note giving the precise
  discrepancy and the wording that would make it true.

## Regenerating

The rows are hand-curated, but they live in code so that CSV quoting, column
order and path validity cannot rot:

```
D:\jepa_phase0\.venv\Scripts\python.exe paper\genai4health2026\scripts\make_claim_evidence.py
```

The generator refuses to write if any `claim_type` or `status` is outside its
vocabulary, if a `claim_id` repeats, or if **any** `evidence_path` does not exist
on disk. That last check is the important one: a row can never cite an invented
artifact. It prints counts by status on success.

It is CPU-only, needs no GPU and no network, and takes under a second.

## Updating

Add or edit a tuple in `ROWS` in
`paper/genai4health2026/scripts/make_claim_evidence.py`, then re-run it. Rules
that keep the map honest:

1. **Never invent a number or a path.** If a claim cannot be traced, the status
   is `PENDING` and the note says what would close it.
2. **Locate by label, not by line.** Sections, macro names and JSON key paths
   survive concurrent editing; line numbers do not.
3. **A resolved `UNSUPPORTED` becomes `SUPPORTED` or `SCOPED-OK` only when the
   artifact changes or the wording changes** - not when someone is satisfied
   that the claim is probably fine.
4. **Do not delete a row when a claim is cut from the paper.** Change its
   `section` to note the removal, so the map records that the claim was
   retired rather than silently losing the audit trail.
5. Keep one row per challengeable assertion. The map targets claims a reviewer
   could contest, not every sentence.

## When to re-run it

- After any edit to the abstract, contributions, results, conclusion, or to an
  appendix the body cites.
- After regenerating `auto/auto_numbers.tex`, since a macro rename silently
  invalidates an `evidence_locator`.
- Before building the submission archive, together with the existing
  consistency, provenance and archive gates.
